# Rin v1.0 hardening and upgrade notes

Version 1.0.0 is the hardened successor to the sealed local `0.3.0` baseline. It keeps the
existing Rin product architecture while tightening its trust boundaries, data integrity,
deployment workflow, and browser delivery.

## Upgrade checklist

1. Back up D1. The unified deploy command now exports a dated remote D1 backup before it
   applies any pending migration.
2. Apply `server/sql/0011.sql`. It deduplicates aliases, usernames, GitHub IDs, and hashtag
   bindings before adding uniqueness constraints and the rate-limit table.
3. Rotate `JWT_SECRET`. Existing sessions are intentionally invalidated after rotation.
4. If GitHub OAuth is enabled, set `RIN_GITHUB_ADMIN_ID` to the numeric GitHub account ID
   that may become administrator. A first-time OAuth user is no longer promoted implicitly.
5. Set `SITE_URL` when scheduled RSS generation is enabled. Optionally configure
   `CORS_ALLOWED_ORIGINS` and `VISIT_RETENTION_DAYS`.
6. Review comment settings. Guest comments are enabled but pending moderation by default;
   automatic publication must be explicitly enabled.
7. Review custom footer HTML. Scripts, event handlers, embedded frames, forms, SVG, styles,
   and unsafe URLs are removed. Move trusted integrations into the application source.

## Completed hardening scope

- Authentication uses expiring HttpOnly cookie sessions; OAuth redirects no longer expose
  JWTs, trust Referer, or create a first-user administrator.
- Password records use salted PBKDF2-SHA256 and upgrade legacy SHA-256 records at login.
- CORS is allowlisted, browser writes are origin-checked, and SPA/static responses receive
  CSP and browser security headers.
- Uploads are administrator-only, image-only, size-limited, and content-addressed.
- Guest comments enforce settings, validation, rate limits, privacy, and moderation.
- Friend/avatar network fetches reject private targets and revalidate every redirect.
- Public search excludes drafts and unlisted posts and uses a separate cache namespace.
- Feed aliases, usernames, GitHub IDs, hashtags, and hashtag bindings are unique at D1 level.
- WordPress import uses multipart files, the authenticated owner, bounded input, safe dates,
  normalized tags, cache invalidation, and AI-summary queue integration.
- PV/UV initialization counts the first visitor; v1.0 no longer stores new raw IP visits and
  scheduled cleanup removes historical rows.
- Shared request schemas now perform runtime validation instead of acting as metadata only.
- Database cache writes use targeted upserts/deletes instead of rewriting the full cache.
- Local/deploy config generation escapes TOML, secrets stay in Worker secrets/dev vars,
  compatibility dates are aligned, and migrations are versioned file by file.
- Client routes are lazy-loaded, and verbose HLL diagnostics are opt-in with
  `RIN_VERBOSE_TESTS=true`.

## Recovery point

The exact pre-v1.0 state remains available at the local annotated tag
`rin-baseline-v0.3.0-20260814` (commit `2c1bbeb`). Do not move that tag.
