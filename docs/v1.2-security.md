# Rin v1.2 security baseline

## Product architecture preserved

Rin v1.2 remains a modern serverless blog built entirely on the Cloudflare developer platform:

- Cloudflare Pages hosts the public application.
- A narrow Pages Functions gateway forwards only API, RSS, and favicon requests.
- A backend-only Worker provides serverless functions and is not exposed on `workers.dev`.
- D1 remains the SQLite-compatible application database and default cache store.
- R2 remains the object store for public image assets; internal cache artifacts are not public.

Queues, cron triggers, and Workers AI remain optional Worker capabilities. ShokaX is unchanged.

## Authentication boundary

Password login is disabled in the UI, shared API contract, runtime service, and deployment
configuration. The legacy `POST /api/auth/login` path always returns `403` so stale clients cannot
reactivate it.

GitHub OAuth is the only login method. All of the following Worker secrets are required:

```dotenv
RIN_GITHUB_CLIENT_ID=...
RIN_GITHUB_CLIENT_SECRET=...
RIN_GITHUB_ADMIN_ID=12345678
JWT_SECRET=<at-least-32-random-bytes>
```

`RIN_GITHUB_ADMIN_ID` must be the creator's numeric GitHub user ID. The callback compares the
verified GitHub profile ID before any local user or token is created. Every other GitHub account is
rejected with `403`, even when GitHub authorization succeeds. Existing legacy users cannot enter
the admin area because middleware rechecks creator identity, admin permission, and session version.

Configure the OAuth callback as:

```text
https://<pages-domain>/api/user/github/callback
```

## Upgrade procedure

1. Back up the production D1 database.
2. Apply `server/sql/0012.sql`. It clears legacy password hashes and adds `auth_version`.
3. Configure all four authentication secrets above and remove legacy password secrets.
4. Rotate `JWT_SECRET`; this invalidates every pre-v1.2 token.
5. Deploy from the repository default branch and test with the creator GitHub account.
6. Confirm a different GitHub account receives `403` and no new `users` row is created.

## Deployment and data isolation

- Pull requests build and test but never deploy production or a privileged preview.
- Production deploy checks out source from the default branch and never trusts downloaded build
  artifacts from a pull request.
- Preview Worker, D1, R2, and external S3 configuration are distinct from production.
- Vite binds to `127.0.0.1` unless `--host` is explicitly supplied.
- Local Workers AI access is disabled unless `WORKERS_AI_REMOTE=true` is explicitly configured.

## Residual operational boundary

Wrangler is updated to the current Cloudflare 4.x line, eliminating the audited Miniflare, Undici,
Sharp, esbuild, and WebSocket findings from that toolchain. Remaining audit notices are confined to
legacy development or CLI dependency chains: Puppeteer's optional browser downloader, ESLint 8,
Drizzle Kit 0.21, and the deprecated i18next parser/build stack. CI skips the Puppeteer browser
download. None of these dependencies enter the deployed client or Worker application bundles; they
remain tracked upgrade debt rather than a claim of a zero-finding development tree.
